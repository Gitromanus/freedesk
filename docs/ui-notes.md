# FreeDesk — заметки по интерфейсу

Короткая выжимка решений по UI, чтобы не восстанавливать их по скриншотам.
Актуально для Windows-клиента и как ориентир для мобильной/веб-версии.

## Окно

- Безрамочное (`FormBorderStyle.None`), заголовок рисуется самим окном: полоса 40 px,
  кнопки «свернуть / развернуть / закрыть» — 40×30 px, в правом верхнем углу.
- `WM_NCHITTEST`: кромки отдаются клиенту, растягивание — вручную (края 6 px),
  курсор на кромке меняется на двустороннюю стрелку. `MaximizedBounds` = рабочая
  область монитора (панель задач не перекрывается).
- Первый клик по неактивному окну должен сразу выполнять действие (активация +
  клик), иначе вкладки и кнопки «срабатывают со второго раза».

## Сайдбар

- Развёрнут — 340 px: `ВАШ ID` (крупно, клик = копировать), строка статуса с точкой,
  поле «9-значный ID», кнопка «Подключиться», «НЕДАВНИЕ» списком.
- Свёрнут — рейл 56 px: шеврон сверху, точка статуса по центру, шестерёнка снизу.
  Разворачивается **только** шевроном (не «+» и не автоматически при каждом подключении).
- Автосворачивание — однократное, при первом подключении; после отключения панель
  возвращается.

## Список «Недавние»

- Строка 44 px: слева точка онлайн/офлайн, имя, справа ID (`Consolas 8.75`).
- Ширина колонки ID считается по тексту (`MeasureText` + 6) — «573 348 635» не
  влезал в фиксированные 84 px, обрезалась первая цифра.
- Нативный скроллбар уведён за правый край панели (он светлый и ломает тему),
  вместо него — свой ползунок 4 px в цвет `#5A6C86`, обновляется по `TopIndex`.
- Иконки «изменить» (✎) и «удалить» (✕) — в правой части строки, видны на активной
  строке/при наведении; их зоны считаются от `Right` минус ширина скрытого скроллбара.

## Вкладки подключений (до 4 сразу)

- Полоска 38 px над областью просмотра, каждая вкладка — отдельный контрол
  (клики обрабатывает Windows, без ручного hit-test).
- Вкладка 126…250 px: точка состояния (зелёная — поток идёт, жёлтая — подключение
  или переподключение), имя устройства, ID мелким, ✕ (зона 26×24).
- Переключение — один клик; `Ctrl+Tab` — следующая, `Ctrl+1…4` — конкретная.
- Видео переключается `Show()/Hide()` дочерних форм: `Visible` у child-форм
  ненадёжен и оставляет кадр от прежней вкладки.

## Панель просмотра

- Одна плавающая полоска по центру сверху (10 px от верха области просмотра):
  `[мониторы 1/2/…] [файл] [отключиться] [свернуть]`, сворачивание — крайнее справа.
- Свёрнутое состояние — только язычок 32×24 с шевроном.
- Панель живёт **внутри канваса** с видео, иначе кадр рисуется поверх неё.
- Стиль: фон `#1B263B`, кромка `#4C6286` — на тёмном видео полоса не теряется.

## Стартовый экран

- Иконка монитора с молнией, заголовок «Готов к подключению», подсказка про ID,
  строка статуса внизу — всё вторичным цветом, без «кадров/разрешения» на экране.
- Статусы — всплывающие (toast), исчезают сами.

## Мобильный/веб-клиент (ориентир)

- Тёмная тема, те же акценты; крупные зоны нажатия (минимум 44 px).
- Видео на весь экран, поверх — тонкая полоса: имя устройства, отключение.
- Ввод: тап = левый клик, долгое нажатие = правый, два пальца = прокрутка.
- Никаких технических статусов на экране — только всплывающие подсказки.

## Проверенные размеры (со скриншотов 1000×660)

- Окно по умолчанию 1000×660, минимум 780×560; при развороте занимает рабочую
  область (2558×1378 на экране 2560×1440 при 125 % масштабе).
- Заголовок 40 px; кнопки — 40×30, центры по X: `W-100 / W-60 / W-20`.
- Сайдбар 340 px, рейл 56 px; поле ID 284×44; кнопка «Подключиться» 284×44.
- Полоска вкладок 38 px: вкладка 126 px (min) на «pc-alpha», ✕ в зоне 26×24 справа.
- Плавающая панель: 94×34 без чипов мониторов, 154×34 с двумя чипами; отступ сверху 10 px.
- Строка «Недавние» 44 px; колонка ID: Consolas 8.75, ширина по MeasureText + 6.
- Ползунок списка 4 px, цвет `#5A6C86`, появляется только при переполнении.

## Наблюдения по поведению

- Клик по неактивному окну должен срабатывать сразу (активация + действие);
  иначе вкладки кажутся «на двойной клик».
- Клик по «+» открывает форму подключения и **не** трогает сайдбар.
- `Show()/Hide()` для встроенных окон просмотра; `Visible` оставлял старый кадр.
- Панель просмотра живёт внутри канваса — иначе видео рисуется поверх неё.

## Диагностика «чёрного экрана» (из тестов 26–27.10)

Симптомы и причины (проверено на живых прогонах):

| Симптом | Причина | Как отличить |
|---|---|---|
| Соединение есть, кадров нет | хост старой сборки (не знает `codec: "jpgdata"`), отвечает MJPEG/RTP | лог хоста: `поток (h264)` вместо `поток (jpgdata)` |
| `setRemote: Incompatible send direction` | браузер предлагал `recvonly`, хост отвечал несовместимо | лечится оффером `sendrecv` |
| Кадры идут (`bytes>0`), `framesDecoded=0` | H.264 в RTP в формате, который Chrome не разбирает | поэтому и сделан режим `jpgdata` |
| Экран чёрный, но подсказка про версию видна | клиент получил ответ без поддержки `jpgdata` | поле `echo` в answer от новой сборки |

Рабочий режим для веба: SDP как H.264 + JPEG-пакеты `[0xF1][seq:2][len:4][JPEG]` по data channel,
ограничения `10 fps / q<=60 / width<=1280` (~5 Мбит/с на активном экране).
Виндовый путь (RTP H.264/MJPEG) при этом не меняется.

  `438 275 139` (консольный, пароль `web-1234`).
- Клиент m.html: `__fdState()` в консоли браузера отдаёт pc/ice/sig/dc, счётчик кадров,

## Статус сети (27.10, важно)

- **Wi-Fi: работает.** Телефон в той же сети ходит по host-кандидатам.
- **4G: не соединяется.** Значит нужен srflx/relay-путь: либо у домашнего роутера
  симметричный NAT, либо мобильный оператор режет UDP. Проверка TURN — открытый вопрос,
  публичный `openrelay.metered.ca` часто недоступен.
- Вывод для продукта: без своего TURN (coturn на VPS) мобильный интернет — лотерея.
